## Overview

A workflow has one **When** trigger and one or more ordered **Then** actions. The tables list the catalog returned by Vala's Workflow API. Names describe the event or action; filters and action configuration determine the precise behavior. Availability and valid combinations depend on the trigger context and your organization.

## When to use

Use this catalog to choose a workflow in the builder or identify types for an external integration.

## Prerequisites

- Access to Workflows in the full CRM.
- For integrations, a key with `workflows:read` to read the catalog and `workflows:write` to create or update workflows.

## Step-by-step

1. Choose a **When** event and configure its filters. Date-relative triggers use a supported deadline or due date; scheduled triggers run daily or weekly and do not carry a Client or Claim.
2. Choose and configure the ordered **Then** actions. Many actions require a Client or Claim in the trigger context. Resource-specific actions also require the appropriate organization resource.
3. Review the workflow before activating it and inspect **History** after it runs.

External agents can call `list_workflow_catalog` through Vala MCP or the External API endpoints `GET /external/v1/workflows/trigger-types` and `GET /external/v1/workflows/action-types` for the current catalog. API and MCP creates are drafts; updates return workflows to draft. Activation requires explicit confirmation through the status operation. See **Organization settings > Integrations > API Keys** for integration guidance.

## Best practices

- Use **Document processing complete** when an action needs processed document content; an upload event may be too early.
- **Submitted to VA** includes staff-confirmed QuickSubmit handoffs. It does not prove VA receipt.
- Check live catalog responses as capabilities evolve, and review action configuration and permissions before activation.

## Common mistakes

- Using a scheduled trigger with an action that requires a Client
- Running overlapping notifications for both a VA handoff and a Claim status change
- Treating a catalog type as proof that every combination or organization is supported

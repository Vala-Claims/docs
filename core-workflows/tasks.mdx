## Overview

Tasks help teams keep follow-up work visible and connected to the relevant Vala workflow.

## When to use

Use Tasks for work that needs a clear next action, owner, or follow-up point.

## Prerequisites

- Access to the relevant organization and Client
- A role that permits task changes; read-only users do not see creation controls
- Your team's task-management conventions

## Step-by-step

1. Open **Tasks** in the navigation. Choose the **Tasks** tab for individual work or **Checklists** for grouped work. Filter the list by the relevant Client, assignee, status, priority, or due date.
2. Select **New Task** (**New** on a phone). Enter a clear title and the instructions needed to complete the work.
3. Choose the relevant Client, assignee, priority, status, and due date. Add other assignees, a checklist, or a reminder when needed. A task opened from a Client record can have that Client fixed as its context.
4. Select **Create Task**. Confirm that the task appears in the expected Client or list; check active filters if you cannot find it.
5. Open the task to review or edit its details. Update its status as work progresses and mark it complete only after checking the result. Use the status filter to find completed work.

Creating a task and creating a reusable task template are different operations. Check the selected context before saving work intended for a specific Client.

## From a Client record

Use the **Tasks** tab in a Client record for follow-up work scoped to that Client. You can review active and completed work, create or edit a task, assign it, set priority, status, and a due date, and use a checklist when it is available. Client reminders can help with client-specific timing; standalone reminders and task-linked reminders are available where supported.

Use the global **Tasks** workspace when you need to review work across multiple Clients.

## Best practices

- Use action-oriented task titles.
- Include enough context to complete the work.
- Keep task status current.

## Common mistakes

- Creating vague tasks
- Omitting the Client or matter context
- Marking work complete before verification

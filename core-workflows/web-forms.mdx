## Overview

Create reusable questionnaires in **Templates > Questionnaires**. A questionnaire's questions, answer destinations, settings, and client layout need review before you share it.

## When to use

Collect structured intake or follow-up information using a questionnaire rather than an unstructured message.

## Prerequisites

- Access to **Templates > Questionnaires** in the correct organization
- A writable organization and permission to create or edit questionnaires
- An approved purpose, audience, and plan for where answers should go

## Step-by-step

1. Open **Templates > Questionnaires** and select **New Questionnaire**. **Build with AI** is available when your organization has AI enabled; review any generated questions before use.
2. Add and arrange the questions in the builder. Use **Editor** to choose the Beta or Classic editing experience. The editor choice is separate from the client layout.
3. Review each answer destination. **Response only** keeps an answer on the submission rather than reusing it on a Client profile. Use the Classic editor when you need the client-field mapping controls.
4. Open **Settings** and confirm the questionnaire's intended use and response behavior. Do not assume every questionnaire creates a Client record.
5. Select **Preview** and check the client layout, required questions, instructions, and answer choices.
6. Select **Save & Publish** when the questionnaire is ready. On narrower layouts the button may show **Save**.
7. Use **Share** to choose the available link or sharing option. Review the published questionnaire before sending its link to the intended audience.
8. Review the collected responses in the questionnaire's responses view and check any mapped Client information before relying on it.

## Best practices

- Explain why you need the information and ask only relevant questions.
- Check destinations before publication. An answer stored as **Response only** is not automatically available for profile or form reuse.
- Preview after changes and follow your organization's approval process before sharing.

## Common mistakes

- Looking for the older **Web Forms** label
- Confusing the editor choice with the layout respondents see
- Sharing before reviewing the published version
- Assuming every response creates or updates a Client profile
